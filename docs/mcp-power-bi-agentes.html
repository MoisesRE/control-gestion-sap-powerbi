Conectar un proyecto Power BI a un agente con MCP

MCP no es un modelo de IA ni un botón mágico dentro de Power BI. Es el protocolo que permite que un cliente de agente encuentre herramientas y las use. Primero hay que decidir si el agente va a editar archivos o responder preguntas sobre datos publicados.

i

Separar construir de consultar

Microsoft documenta caminos distintos: Power BI Authoring MCP crea y modifica modelos; Fabric IQ MCP consulta datos gobernados. El endpoint antiguo de consumo sigue documentado para integraciones existentes, pero Microsoft recomienda Fabric IQ para nuevas experiencias de consulta.

Qué servidor usar

ObjetivoRutaQué revisar
Editar PBIP/TMDL o un modelo abierto en DesktopAuthoring MCP localEl servidor remoto no alcanza archivos locales; usa rama Git y revisa el diff.
Modificar un modelo de un workspace FabricAuthoring MCP alojado o localEl endpoint alojado requiere habilitación del administrador; escribir exige permisos.
Responder preguntas sobre un modelo publicadoFabric IQ MCPEs la ruta de consumo; mantiene permisos y reglas por filas/objetos.

Un flujo que deja rastro

  1. Prepara el proyecto. Abre el PBIP desde una copia bajo control de versiones; describe tablas, métricas, reglas y alcance.
  2. Conecta el cliente MCP correcto. VS Code puede actuar como host con un cliente de agente; el servidor expone operaciones. La identidad necesita autorización y permisos adecuados.
  3. Empieza por leer. Pide al agente que liste el modelo y explique las medidas antes de permitir cambios. Acota archivos y objetos que puede tocar.
  4. Genera, valida y revisa. Solicita una consulta DAX de validación y revisa resultados y diff. Para una página, inspecciona el render final, no solo el archivo.
  5. Publica por el proceso normal. La revisión humana y la aprobación siguen siendo importantes: un agente con permisos de escritura puede cambiar objetos reales.
Ejemplo de instrucción al agenteSolicitud
Lee el modelo y explica cómo calcula la ejecución presupuestaria. Propón una medida que respete los filtros y periodos cubiertos. No edites los roles de seguridad. Valídala con DAX y presenta el diff para revisión antes de guardar.

Permisos y estado del producto: Authoring MCP local puede trabajar con PBIP/TMDL en disco; el servidor alojado opera con modelos del workspace, no con archivos locales. Fabric IQ MCP está orientado a consultas. Revisa la etiqueta preview/GA y los permisos del tenant antes de desplegar.

Qué están probando los equipos

En LinkedIn, Richa Pandit mostró una orquestación entre un modelo semántico, un informe Power BI y un agente de Copilot Studio conectado con Fabric IQ MCP. Tiffany Lin describió un experimento de presupuesto vs. real con skills y MCP: el agente armó un primer borrador y su trabajo pasó a enfocarse más en fijar reglas y revisar cambios. Son experiencias personales, no benchmarks, pero ayudan a ver cómo se ensamblan las piezas.

Para un PBIP como el de este sitio, empezaría con el servidor local para modelar en una rama y reservaría Fabric IQ para preguntas sobre el modelo publicado.
